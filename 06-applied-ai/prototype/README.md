# freightdoc: the pilot code

Python 3.11+, standard library only. No API key, no dependencies, under a second for the full evaluation.

```bash
cd 06-applied-ai/prototype
python -m unittest discover -s tests -t .      # unit tests, incl. the evaluation gate
python -m evals.run --gate                     # ablation, threshold sweep, test results, release gate
python -m freightdoc batch --set test          # how the 220 test documents are routed
python -m freightdoc queue --set test          # the review queue a clerk would see, with reasons
python -m freightdoc read DOC-0084             # one document: fields, confidence, checks, route, TMS record
python -m freightdoc rules                     # validation rules V01-V14
python scripts/make_data.py --check            # data sets match their recipe
```

With Claude instead of the offline provider: `pip install anthropic`, set `ANTHROPIC_API_KEY` (or `ant auth login`), then add `--provider claude` to any command. `python -m evals.run --provider claude` calls the API once per document of both sets (440 calls; the ablation and sweep reuse the reads), which costs money; it writes `evals/report-claude.json` and `.md`.

```
freightdoc/
  reference.py        LOCODEs, Incoterms, currencies, ISO 6346, label glossary (EN/NL/FR/DE)
  extract.py          offline provider: classify + extract with confidence
  providers/claude.py Claude provider: structured output, status per field, fallbacks
  validate.py         rules V01-V14
  pipeline.py         linking, routing policies A-D, TMS record
  __main__.py         command line
prompts/extract.md    the extraction prompt (versioned with the code)
schema/               JSON Schema of the TMS record
evals/                run.py, thresholds.json (the release gate), report.json/.md (generated)
data/dev, data/test   220 synthetic documents each + truth (generated by scripts/make_data.py)
tests/                unit tests
```
